## 0. 一句话

**整个 App 就是一张自上而下的解剖画布**：总量 → 去哪了 → 每一块是什么 → 就地处理。所有回收动作统一走预演（一个交互句式）；工具不是平行卡片堆，而是从分组里长出来的下钻；rail 收缩到 3 项。

## 3. 解剖画布（首屏）组件规格

自上而下：
1. **Hero**：`你的 NNN GB，去哪了`（大标题）+ 副行（健康 · 占满预测）+ 构成条（按 cause 着色的分段条）+ 按钮行（`ⓐ 安全快捷回收 · 预计 X GB` / `+` 菜单 / `重新扫描`）。扫描中：此区变为进度态（当前路径 + 进度条 + 取消），画布其余部分淡出。
2. **DiskHealthCard**：紧凑卡（保留 P1 落位）。
3. **扫描未覆盖卡**：诚实文案（P0 键复用）。
4. **动态 cause 分组**（找到才出现，totalBytes 降序）：组卡 = 图标 + 标题 + 措辞行（该 cause 的诚实定性）+ 总字节 + `就地清理` 按钮。展开态（默认展开前 2 组）显示组内条目行：条目名 + 字节 + 徽章（✓ 可回收 / ⚠ 数据不属垃圾 / 迁出引导 / 不动）。每组的按钮动词随 cause 变化（清理/正确解法/迁出引导）。
5. **系统状态条**：启动项 N 个 · 已装应用 N 个有残留 → 点入下钻。
6. **拒答区**：虚线卡「我不敢判的 · N 项」——不在建议里，点开看缺什么信息。
7. **规则链接**：`我们据以判断的每一条规则…→`
8. **「+」菜单**：粉碎窗 · 归因规则 · 维护。

## 4. 交互统一（核心原则）

**全 App 只有一种清理句式：看清单 → 确认。**
- 组头「就地清理」→ 该组预演（1:1，沿用 P1 `CleanupRehearsal`）
- hero「安全快捷回收」→ 推荐项预演（已勾选好）→ 确认执行（**废除 P1 的两层信任豁免**——统一后快捷回收也过预演；推荐项全部 ✓ 可回收 + 30 天兜底，预演是快速确认不是负担）
- 下钻页勾选 → 预演 → 执行
- 未购买：预演可见，确认时被拒 → 付费墙（P1 语义不变）
- **1:1 契约全链路有效**：预演清单 == 执行清单（spec §10 P1 验收延续）

## 5. 扫描即动作，非页面

- 触发：hero `重新扫描` / ⌘R / Onboarding 完成后自动首扫 / 菜单栏
- 扫描中：hero 区切换为进度态（`Scanning...` + 当前路径 + 取消），分组区淡出（不清空——上次结果保留但变灰）
- 完成：分组刷新（`.onChange(hasScanning)` 管道沿用 P1 修复波机制）+ 完成横幅（释放预估）

## 6. 分组下钻页

- 入口：组卡点击（非按钮区）
- 内容：面包屑（← 解剖 / 组名）+ 文件级列表（每项：名称/大小/理由开关/危险项警示）+ 节点问答（AssistantNodePanel 迁入）+ 底部 `预演并清理`（组内勾选集）
- 数据：ScanResultsViewModel 四级树按 cause 过滤（原树结构不变，视图按组切片）

## 8. 视觉语言

- **徽章四色语义**（全 App 唯一色彩系统）：绿 `✓ 会回来` / 蓝 `迁出引导` / 橙 `⚠ 注意` / 红 `数据·不属垃圾` / 灰 `不动·不敢判`
- 单一强调色（系统蓝）；SF Symbols；大标题排版（`.largeTitle` hero）；分组卡 = 白底圆角 12 + 1px 描边；深色模式全适配
- 留白节奏：分组间距 12pt、卡内 16pt、页面边距 28pt
